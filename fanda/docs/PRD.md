# 饭搭 — 产品需求文档 (PRD)

---

## 1. Executive Summary

**饭搭**是一款面向都市打工人的智能饮食决策助手。产品以"告别每天吃什么的灵魂拷问"为核心切入点，通过趣味转盘推荐、饮食日历记录、餐饮预算管理、拼饭社交四大模块，帮助用户快速做出用餐决策、科学管理饮食开支、拓展职场社交圈。

产品采用活泼可爱的视觉风格，以轻松有趣的交互降低用户使用门槛。MVP阶段聚焦单机体验，通过本地存储实现核心功能，后续逐步接入后端服务，打通社交与LBS能力。

**MVP目标：** 在无后端依赖的情况下，交付一个功能完整、体验流畅的移动端应用，覆盖"选餐—记录—控预算"的完整闭环。

---

## 2. Mission

**产品使命：** 让每一顿饭都不再纠结，让打工人吃得开心、花得明白。

**核心原则：**
- **极简决策** — 3秒内给出一个靠谱的用餐建议，不让用户再犹豫
- **有趣不无聊** — 用转盘、成就、徽章等游戏化设计让记录饮食变成乐趣
- **省钱有数** — 实时追踪餐饮开支，帮用户守住钱包
- **社交连接** — 让"一起吃饭"成为打工人最自然的社交方式
- **隐私优先** — MVP阶段数据全部本地存储，用户数据不上传

**核心功能：**
- ✅ 转盘随机推荐菜品（支持偏好过滤）
- ✅ "不想吃"排除法快速缩小选择范围
- ✅ 饮食日历记录每日三餐
- ✅ 月度/周度餐饮预算设定与追踪
- ✅ 个人口味偏好设置（辣度、口味、忌口）
- ✅ 收藏喜欢的菜品
- ✅ 成就徽章系统

**技术：**
- ✅ uni-app (Vue 3) 跨平台框架
- ✅ Pinia 状态管理
- ✅ 本地存储（uni.storage）数据持久化
- ✅ H5 + 微信小程序双端适配

**部署：**
- ✅ H5 网页版可直接访问
- ✅ 微信小程序发布

### Out of Scope（后续迭代）

- ❌ 后端服务器与用户账号体系
- ❌ 真实LBS定位与附近餐厅接入（如高德/美团API）

- ❌ AI智能推荐（基于机器学习的个性化推荐）

- ❌ 原生App发布（iOS/Android）

## 5. User Stories

### 核心用户故事

**US-1: 快速决策**
> 作为一个纠结午餐吃什么的打工人，我想要转一下转盘就得到一个推荐，这样我不用再花10分钟纠结。

*示例：小林打开饭搭，点击转盘，3秒后转盘停在"黄焖鸡米饭"，她觉得不错，点击"就吃这个"，自动记录到今日午餐。*

**US-2: 排除法选餐**
> 作为一个知道自己不想吃什么但不知道想吃什么的用户，我想要通过排除不想吃的类别来缩小范围。

*示例：小林点击"不想吃"，依次排除了"面食"和"快餐"，转盘自动移除这些选项，剩余选项中再转一次。*

**US-3: 饮食记录**
> 作为一个想管理饮食的用户，我想要快速记录每餐吃了什么和花了多少钱，这样月底能看到完整的饮食报告。

*示例：阿杰中午吃了沙拉，花了28元，他在日历页点击"午餐"，选择菜品类型"沙拉"，输入金额，1秒完成记录。*

**US-4: 预算管控**
> 作为一个月底经常餐饮超支的打工人，我想要设定每月餐饮预算并实时查看剩余额度，这样我能合理分配每天的餐费。

*示例：小林设定月预算2000元，已过半月花了1200元，系统提示"本月预算偏紧，建议今天控制在25元以内"，并自动推荐对应价位的菜品。*

**US-5: 拼饭找搭子**
> 作为一个想找同事一起吃饭的新人，我想要看到附近有谁也在找饭搭子，这样我能方便地约人一起吃。

*示例：小王在拼饭广场看到同楼层的人发了"12点去楼下湘菜馆，还差1人"，他点击"加入"，成功组局。*

**US-6: 口味偏好**
> 作为一个有忌口的用户，我想要设置我的饮食偏好，这样推荐的菜品都是我能吃的。

*示例：用户设置"不吃香菜、不吃辣、海鲜过敏"，之后转盘推荐会自动过滤掉含这些元素的菜品。*

**US-7: 成就激励**
> 作为一个容易半途而废的用户，我想要通过成就系统获得记录饮食的成就感，这样我能坚持使用。

*示例：连续记录7天后解锁"饮食达人"徽章，页面弹出可爱的撒花动画。*

## 7. Tools/Features

### 7.1 转盘推荐模块

| 功能 | 说明 |
|------|------|
| 智能转盘 | CSS3旋转动画，停在随机菜品上，支持偏好过滤 |
| 排除法 | 点击"不想吃"标记排除类别，缩小推荐范围 |
| 换一个 | 不满意可重新转，排除已推荐项 |
| 就吃这个 | 确认选择，自动记录到今日用餐 |
| 时段感知 | 根据当前时间（早/中/晚）推荐对应餐食 |

### 7.2 饮食日历模块

| 功能 | 说明 |
|------|------|
| 月历视图 | 日历格展示，有记录的日期标记小圆点 |
| 三餐记录 | 每日分早餐、午餐、晚餐三个卡片槽位 |
| 快速录入 | 从菜品库选择或手动输入，记录菜品+金额 |
| 营养标签 | 简易标注（主食/肉类/蔬菜/水果）比例 |
| 重复检测 | 连续3天吃同类食物时友好提醒 |

### 7.3 预算管家模块

| 功能 | 说明 |
|------|------|
| 预算设定 | 设置月度/周度餐饮总预算 |
| 实时追踪 | 环形图展示已花/剩余比例 |
| 每日建议 | 根据剩余预算计算每日建议额度 |
| 消费明细 | 按日/周/月查看消费流水 |
| 超支预警 | 接近或超出预算时弹出提醒 |
| 趋势图表 | 周/月消费趋势折线图 |

### 7.4 拼饭社交模块（MVP模拟数据）

| 功能 | 说明 |
|------|------|
| 拼饭广场 | 瀑布流展示附近拼饭邀请 |
| 发起拼饭 | 填写时间、地点、人数、想吃的类型 |
| 投票选餐 | 多人投票决定去哪家吃 |
| 加入/退出 | 一键加入或退出拼饭局 |

### 7.5 个人中心模块

| 功能 | 说明 |
|------|------|
| 偏好设置 | 口味偏好（辣度1-5）、忌口列表、喜好类型 |
| 收藏夹 | 收藏喜欢的菜品，方便快速选择 |
| 成就徽章 | 连续记录、尝鲜达人、省钱高手等成就 |
| 数据概览 | 本月餐数、总花费、最爱菜品统计 |

## 9. Security & Configuration

### 数据安全
- MVP阶段所有数据存储在设备本地（uni.storage）
- 不采集用户位置、通讯录等敏感信息
- 无用户账号体系，无需登录即可使用

### 配置管理
- 应用配置通过 `manifest.json` 管理
- 页面路由通过 `pages.json` 管理
- 全局样式变量通过 `uni.scss` 管理
- 菜品数据通过 `data/foods.json` 管理

### 安全范围
**In Scope:**
- ✅ 本地数据存储安全（不存储敏感信息）
- ✅ 输入校验（预算金额、文本长度）

**Out of Scope:**
- ❌ 用户认证与授权（MVP无账号体系）
- ❌ 数据加密传输（MVP无网络请求）
- ❌ 第三方API安全（MVP无外部接口）

## 11. Success Criteria

### MVP成功定义
一个可在H5浏览器和微信小程序中运行的完整应用，用户可以独立完成"选餐—记录—管预算"的完整流程。

### 功能要求
- ✅ 转盘推荐可正常旋转并给出菜品结果
- ✅ 排除法可正确过滤不想吃的类别
- ✅ 日历可记录并展示每日三餐
- ✅ 预算设定后可实时追踪消费
- ✅ 偏好设置可影响推荐结果
- ✅ 数据在关闭应用后仍然保留（本地持久化）
- ✅ 拼饭广场UI完整展示（模拟数据）

### 质量指标
- 转盘动画流畅，无明显卡顿（60fps）
- 页面切换过渡自然
- 首屏加载时间 < 2秒
- 所有交互有即时反馈（点击态、加载态）

### 用户体验目标
- 新用户无需教程，3分钟内完成首次转盘推荐
- 记录一餐操作步骤 ≤ 3步
- 视觉风格统一，配色和谐，符合"活泼可爱"定位

## 14. Risks & Mitigations

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| **菜品数据库覆盖不足** | 用户觉得推荐单一 | 初始提供100+菜品，支持用户自定义添加 |
| **本地存储容量限制** | 长期使用数据丢失 | uni.storage有5-10MB限额，定期清理旧数据，后续迁移云端 |
| **转盘动画兼容性** | 低端机型卡顿 | 使用CSS3 transform替代JS动画，提供降级方案 |
| **用户留存低** | 新鲜感过后弃用 | 成就系统+连续记录奖励增加粘性 |
| **拼饭社交冷启动** | 无真实用户时体验空洞 | MVP用模拟数据展示，先打磨单机功能再开放社交 |
